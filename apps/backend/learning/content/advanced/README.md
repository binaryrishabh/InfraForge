# Advanced practice

Four executable labs use the existing challenge engine, recorded attempts, prediction
verification and generic report controls. No new judge or diagnosis store is introduced.

- `diagnose-lost-app-capacity`: a refused dependency probe leaves one app carrying the
  workload. Verify the existing database-admission prediction on an unchanged attempt,
  then compare flow capacity. This sequence is instructional, not an edit lock. The
  broad `other-or-mixed` answer needs the retained firewall counters to narrow its cause.
- `investigate-a-pool-reset`: CPU reduction followed by a one-shot transport reset.
  Reconstruct exact action order and later caller outcomes. Immediate before/after-reset
  service improvement is Unknown because scenario reports retain no continuous trace.
- `budget-for-a-partition`: fixed traffic and a single app-link partition. Two passing
  peer sizes trade educational cost against sampled spare CPU. Constraints are checked
  by the engine; recommendations and incident prose receive no grade or hiring judgment.
- `trace-a-saturation-cascade`: DB CPU and occupied connections affect caller wait and
  failures. This does not prove session exhaustion, VM admission-queue pressure, retry
  amplification or per-path allocation of every waiting millisecond.

Each lesson names further limits. Parameter assumptions and cost estimates are educational.
All latency criteria use completed requests in the exact evaluation second, never a
whole-run SLO. Caller populations remain visible separately. Healthy samples do not prove
continuous health, recovery time or production availability.

Not offered: arbitrary free-text root-cause verification; a reset-benefit/recovery-time
exercise without retained intermediate measurements; database-member failover scenarios
(the scenario compiler restricts member outages/promotions to Free World); VM process
outage via a made-up scripted intervention; packet diagnosis or provider benchmarks.
Earlier labs and their published definitions remain unchanged. Human review receipts
must come from the learning authoring workflow; these labs do not manufacture them.
