# Cross-resource fault and recovery contracts

Fault ending permits future progress; it does not prove recovered data, drained
backlog, successful retry or fresh observation. Profiles below are scoped logical
interventions, not a universal physical crash/restart function. The legacy visible
Crash/Disk failure/Memory leak controls cannot be promoted without resource-specific
contracts and evidence.

| Resource | Actual intervention / retained and lost ownership | New and existing work | Recovery and remaining Unknown |
| --- | --- | --- | --- |
| Compute | Service pause retains admitted workers/queues and freezes CPU; quota/capacity/competitor interventions alter scheduler capacity/work. Artifact ownership is separate. | Offline/not-ready paths refuse new establishment or prevent delivery; admitted local work follows explicit pause/cancellation. | Unpause resumes retained work; artifacts still gate readiness. Physical process death, RAM loss, OS/GC/OOM, provisioning and restart are Unknown. |
| Network / LB | Partition discards transfers; bandwidth/delay settle real bytes. Reset closes owned connections; drain stops selection and owns a grace deadline. LB retains routing/probe state. | Pool/response timers own failures; delivered remote work may continue under configured cancellation. Probe/detection lag affects eligibility. | Fault end enables later transfers/selection; dropped messages do not reappear. Existing requests need their own retry/timeout. LB control-plane probes remain separate from front-door service availability; physical TCP/replica crash is not claimed. |
| Database | Service unavailability aborts queued/active transactions, releases locks/sessions and retains committed rows. | Aborted work stays aborted; requests during outage fail/wait through actual path rules. | Future statements/transactions can use new logical sessions. No automatic transaction replay. WAL/fsync/physical recovery/replication remain Unknown. |
| Cache | Pause aborts commands and retains entries; TTL still governs validity. Explicit flush separately clears entries and advances invalidation epoch. | Valid hits may spare an unavailable DB; misses/fallback create actual DB work. | Returning service may be warm after pause or cold after authored flush; actual fills restore contents. No universal restart-causes-cold assumption or persistence claim. |
| Queue | Broker pause aborts commands, retains accepted logical messages; lease/retention clocks continue. Worker crash abandons local ownership and cancels local CPU/timers. | Old receipts can expire; delivered remote effects can finish. New actual attempts may duplicate effects or DLQ. | Returning worker polls/drains through real capacity. Retention/DLQ losses stay terminal. Physical broker persistence/replication is Unknown. |
| Object storage | Service/read/write outage retains committed objects; capacity restriction retains existing bytes. Pending command timeout/cancel before commit prevents mutation. | Once committed, lost responses do not undo it. Reads/writes fail according to their actual phase/access. | Later retries can succeed; failed requests do not automatically become successful. Disk, replica, destructive loss and physical repair are Unknown. |
| DNS | Authority retains records; resolver retains cached snapshots. Pause aborts commands; expiry timers continue. | Valid cache can survive authoritative outage; expired/new queries fail or time out. Established connections retain selected destinations. | New queries after return can refill with new generation. Cached old records and failed requests do not magically change. Recursive propagation/DNSSEC/physical service timing remain Unknown. |
| CDN | Cached complete objects survive logical service/origin outage until TTL/purge/eviction. Front-command cancellation removes its waiter; a shared fill can remain owned by others. | Valid warm hits can succeed while origin fails. Expired/missing requests issue actual origin work. | Old pending fills can fail after origin return; fresh later requests refill. Purged generations reject older fills. Full HTTP/stale/edge/storage behavior remains partial. |
| Firewall / TLS | Rule replacement retains admitted stateful flows. Close/reset/idle expiry removes exact flow ownership. Certificate assertions are checked on new session creation. | New flows obey current rules/listeners/identity/time. Established return traffic uses owned state, including after policy changes. | Restoring an allow rule enables later connections; it does not resurrect failed requests. Destructive flow loss, packet/kernel behavior and physical TLS crypto/timing remain Unknown. |
| Registry / startup | Registry pause retains blob/manifest/tag metadata and object contents; node caches retain completed layers. Incomplete remote writes can outlive a failed reply. | Running replicas remain running. New startup resolves a manifest and acquires missing layers; failure leaves readiness false. | Only authored retries resume startup. Already-resolved images do not follow tag mutation. Physical artifact persistence, verification CPU, unpack/execute and OCI auth/GC remain Unknown. |
| Monitoring | Agent pause aborts collection/export commands and retains queued telemetry. Backend pause retains received samples. Finite buffers/retries cause explicit discard. | Application reality continues independently. Samples can be stale/missing; ambiguous export may already have arrived. | Future observations resume without filling historical gaps. Backend/agent ages differ. Durable telemetry loss/restart, target instrumentation demand and arbitrary logs/traces remain Unknown. |

`m2g-proofs.json` retains DNS cached/fresh failures, CDN warm/expired/pending/recovery,
DB firewall denial, missing listener, four TLS compatibility cases, new/existing
policy flows, registry blocked/readied startup, monitor gaps, export loss, queue
dependency backlog and cache-fallback DB work. Native reference observations are
separate and do not certify these profiles as provider implementations.
