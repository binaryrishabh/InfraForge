# Local G7 cache pilot

G7 runs pinned Valkey 8.1.3 and Bun 1.3.14 inside one disposable container with
no network, capped at 2 CPUs / 2048 MiB (swap disabled), with a 240-second
external watchdog. Raw JSONL is written to the container filesystem and copied
out after exit. The runner refuses an occupied host container slot; the existing
Docker build service is excluded. The image inputs are immutable digest pins in
`g7-manifest.json` and `G7.Dockerfile`. Persistence is explicitly disabled.

Two repetitions each cover noeviction/sampled allkeys-lru, 64/2048-key working
sets and cold/warm inventories. Values have exactly 4096 bytes. Maxmemory is
4194304 bytes; warm inventories are installed before that cap is applied, so
the large warm case deliberately starts above the cap. Every actual lookup and
fill acknowledgement/rejection is recorded. INFO hit/miss deltas reconcile with
the retained keys; evicted/expired/rejected-command counters, commandstats,
used_memory/dataset/RSS, process/cgroup CPU/memory/IO and victim sets are retained.
The independently withheld square-modulo trace has 4096 recorded lookups.

Three completed same-key GETs precede a backing-function barrier, with and
without app coalescing. The 20 ms hold is authored stimulus, not origin demand.
TTL retains actual PTTL and before/after GET/expired counters. Write invalidation
retains an actual refused stale fill through a single-app generation guard and
a subsequent version-2 read. This is application policy, not a Valkey generation
primitive or a distributed coherence claim.

Backing calls are real in-process keyed function calls. This pilot does not
measure PostgreSQL CPU, physical DB work saved or a full LB/app/PG/cache stack;
G10 owns that separate experiment. INFO command execution microseconds are not
per-command CPU core-time; the latter stays Unknown. The main windows use a
single serial issuer with no app pool contention; they cannot calibrate pool
waiting. Exact-LRU semantic tests do not require Valkey's sampled victim order.
No universal bytes/key, cloud timing, managed-node or calibration claim follows.

Run from the repository root with pinned Bun and Docker:

```powershell
bun --no-env-file scripts/reality/first-stack-pilots/g7-run.ts C:/external/new-g7
bun --no-env-file scripts/reality/first-stack-pilots/archive.ts C:/external/new-g7
bun --no-env-file scripts/reality/first-stack-pilots/g7-summary.ts --write C:/external/new-g7
bun --no-env-file scripts/reality/first-stack-pilots/g7-summary.ts --raw C:/external/new-g7
bun --no-env-file scripts/reality/first-stack-pilots/g7-summary.ts
bun --no-env-file --no-install test scripts/tests/g7Pilot.test.ts
bun --no-env-file node_modules/typescript/bin/tsc --noEmit -p scripts/reality/first-stack-pilots/tsconfig.json
```

The committed record retains 17 windows and compressed recorded-key/hit/fill
sequences, not a fitted ratio. External raw artifacts have exact byte hashes;
the summary also pins LF-normalized producers. Static CI reconstructs populations
and rejects missing keys, counter drift, lost windows and timing promotion.
Raw replay additionally reconstructs the entire summary from the capture.
Model 2 remains inactive; all composed timing remains assumption-only.
